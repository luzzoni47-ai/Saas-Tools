Questions

Frequently asked questions

Everything about privacy, algorithms and file support.

Is my text uploaded to a server?

No — and that's not marketing. Every comparison runs inside your browser tab using JavaScript. There is no backend endpoint, no database and no analytics on your content. You can disconnect from the internet after the page loads and the tool keeps working.

What diff algorithm do you use?

We use the Myers shortest-edit-script algorithm (O(ND)) with common prefix and suffix trimming, which is the same family of algorithm used by git diff. After line alignment, a second character-level Myers pass runs on each changed line pair to isolate exactly which characters were inserted or deleted.

Which file formats can I compare?

Any plain-text format: .txt, .json, .js, .ts, .md, .csv, .xml, .html, .css, .sql, .py and more. Binary files (images, PDFs, archives) are not supported because they aren't text.

Is there a file size limit?

There is no artificial limit. Because the entire comparison happens locally, the only ceiling is your browser's available memory. Documents with tens of thousands of lines compare comfortably, and the prefix/suffix trimming pass keeps typical edits near-instant.

What's the difference between Split and Unified view?

Split view puts the original and modified text in two aligned columns so you can read them in parallel. Unified view merges both into a single column with - and + markers, exactly like a git patch — which is handy when you want to paste the result into a commit or a ticket.
