FAQ

Base64 questions, answered

Base64 maps binary or text data onto a 64-character ASCII alphabet (A–Z a–z 0–9 + /) so it can travel safely through systems that only accept plain text. You'll find it in JSON payloads, data URLs, MIME email attachments, JWTs and HTTP Basic Auth headers. It is encoding, not encryption — anyone can reverse it.

Yes. Your input is first converted to UTF‑8 bytes, then Base64-encoded — so emoji 🚀, Arabic, Japanese, Chinese and every other Unicode code point round-trip perfectly. Many older tools call btoa() directly on the string and corrupt anything outside Latin‑1.

Standard Base64 uses +, / and =, which need percent-encoding in URLs. URL-safe Base64 (RFC 4648 §5) swaps them for - and _ and drops padding — essential for JWT segments, query params and filenames. Flip the toggle above; the decoder accepts both formats automatically.

There's no imposed limit — the only ceiling is your browser's available memory. Multi-megabyte strings convert in a few milliseconds because the heavy lifting is done by native browser APIs rather than JavaScript loops.
