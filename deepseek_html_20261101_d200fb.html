FAQ

Questions, answered.

Is this MD5 / SHA-256 hash generator safe and private?
Yes. Every digest is computed locally in your browser — SHA family hashes through the native Web Crypto API, and MD5 through a pure-JavaScript implementation. Your text and files never leave your device. There is no server, no upload endpoint and no logging.
Can I decrypt or reverse an MD5 hash?
No. Hashing is a one-way function by design — there is no mathematical inverse. Sites offering "MD5 decryption" simply look your hash up in a giant table of previously-seen inputs. If your input isn't in that table, it can never be recovered.
Which algorithm should I use: MD5, SHA-1, SHA-256, SHA-384 or SHA-512?
For anything security-related, use SHA-256 (the modern default) or SHA-512 for maximum strength. SHA-1 and MD5 are cryptographically broken and should be limited to legacy compatibility or non-security checksums like cache keys.
Can I generate a checksum for a large file?
Yes. Switch to File mode and drag the file in — or drop it anywhere on the page. It's read with the FileReader API and hashed entirely in memory, so even multi-hundred-megabyte files work on modern browsers. Nothing is transmitted over the network.
Why do I get the same hash every time for the same input?
That's the defining property of a cryptographic hash: it's deterministic. Identical input always produces identical output, which is exactly what makes hashes useful for verifying that a file hasn't been altered.
Should I hash passwords with SHA-256 or MD5?
No. General-purpose hashes are far too fast to store passwords safely. Use a dedicated password-hashing function such as Argon2id, scrypt or bcrypt, always with a unique per-user salt and a high work factor.
